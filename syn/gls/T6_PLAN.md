# T6 — GLS + PPA plan (tilelink_to_AXI4)

T6 is the post-synthesis sign-off: prove the **gate netlist** is functionally correct and
characterise its **PPA**. Adopted from the shared sign-off kit (`dv-swarm-kit/templates/signoff`),
pathfound on `IP-axi-to-2apbs`. The DUT is **Chisel** → generated SystemVerilog (one
self-contained `generated/<top>.sv` per bridge top; git-ignored, regenerated by `make elab`).

## What runs here (OSS, no PDK) — real artifacts

| Step | Command | Artifact | Status |
|------|---------|----------|--------|
| **PPA proxy** | `make ppa` (`syn/ppa/ppa.sh`) | `syn/ppa/reports/<top>.ppa.rpt` | **PASS** for all three tops — TLUHToAXI4 (cells≈3191, flops≈319, depth≈147), TLULToAXILite (303/130/58), TLUCToAXI4 (4248/421/272). |
| **Zero-delay GLS** | — | — | The kit's iverilog-based zero-delay GLS gate is **not applicable** here (see below). The Verilator-netlist recipe is authored below; the OSS run is deferred. |

## Why the kit's `make gls` (iverilog) is not wired here

The kit's T6 GLS gate compiles a Verilog/SystemVerilog **directed, self-checking** TB
against the Yosys gate netlist with **iverilog**, and keys PASS off a `PASSED` line + an
explicit `$finish`. This block's self-checking testbenches are **C++ Verilator harnesses**
(`test/cpp/tb_ulite.cpp`, `tb_uc.cpp`, `tb_chi.cpp`, `tb_main.cpp`) driving the DUT through
Verilator's C++ API — there is no Verilog directed TB for iverilog to drive. Wiring a
no-op/skipping `make gls` would be a hollow gate, so none is added (doctrine: a skip is
"not run", not a pass).

## Authored recipe — Verilator-netlist GLS (the correct OSS path for this block)

The equivalent OSS zero-delay GLS for a Chisel/C++-TB block is to Verilate the **netlist**
instead of the RTL and reuse the existing C++ harness:

1. Synthesize each top to a generic-gate netlist that Verilator can elaborate:
   `yosys -p "read_verilog -sv generated/<top>.sv; synth -top <top> -flatten; write_verilog -noattr syn/gls/<top>.gls.v"`.
2. Verilate the netlist + the Yosys sim models with the **same** C++ TB
   (`verilator --cc --exe syn/gls/<top>.gls.v $(yosys-config --datdir)/sim{cells,lib}.v test/cpp/tb_<x>.cpp`),
   top set to the netlist module, and run the harness scoreboard against the gates.
3. PASS = the C++ harness scoreboard clean against the netlist (same assertion the RTL run uses).

This is a straightforward follow-up (needs the Yosys sim models to Verilate cleanly, which
is the one piece to validate); it is left authored rather than run so nothing green is
claimed without the artifact.

## sky130 P&R and post-route GLS (open PDK)

`make pnr` (LibreLane, CI `silicon.yml`) routes all three tops on sky130A from the
Chisel-emitted SV. **Post-route GLS is n/a here** (not run, not a pass). The sky130_fd_sc_hd
functional models are UDP `primitive`s, which Verilator does not support, and this block has
no Verilog self-checking TB that iverilog could run. Closing it needs one of:
(a) a Verilog/SV directed TB per top (iverilog + the sky130 models, as the sibling blocks do);
or (b) mapping the routed netlist onto behavioural cell models that Verilator accepts, then
reusing the C++ harness (the recipe above).
